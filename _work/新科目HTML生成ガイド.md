## 0. 最重要の心得

1. **解説の厚みが命**。表を足しただけでは産婦人科水準にならない。下記「品質基準」の数値を満たすまで書く。
2. **正解データを絶対に間違えない**。採点は `.ch2.ok` の個数だけで決まる（`ans_label`やバッジは不使用）。ok欠落＝黙って全問不正解。
3. **医学的正確性はユーザーの抜き取り確認が前提**。解説はPDFに無くAIが執筆するので、その旨を必ず伝える。
4. **選択肢が「表」の問題はAIで抽出しない。ユーザーにスクリーンショットを頼む**（§1参照）。列の対応を取り違えて静かに壊れるため。

## 1. データ抽出フロー

### ⚠️ まず「本当に化けているか」を確認する（画像化は最後の手段）

「化けて見える」の大半は**Bashツールの端末出力がcp932で潰れているだけ**で、PDFのテキスト自体は
正常なことがある（精神科PDFがこれ。当初mojibakeと判断して画像化していたが誤り）。判定はこうする:

```python
print([hex(ord(c)) for c in d[p].get_text()[:40]])   # 0x3000/0x672c… なら日本語は取れている
```

取れているなら **全ページをUTF-8ファイルへdumpし、Readツールで読む**のが圧倒的に速く正確
（画像化＋視覚読取は1章あたり数十枚のRead往復になる）。

```python
import fitz, io
d = fitz.open(r'MEC問題文pdf/....pdf')
with io.open(f'{SCRATCH}/all.txt','w',encoding='utf-8') as f:
    for i in range(d.page_count):
        f.write(f'===== PAGE {i+1} =====\n'); f.write(d[i].get_text())
```

本当にToUnicodeが無く化けている場合（例: `ϝοΫ`=MEC）だけ、ページを画像化してReadで視覚的に読む:

```python
d[p-1].get_pixmap(dpi=150).save(f'{SCRATCH}/p{p}.png')   # 1問3枚前後/ページ
```

### 巻末の解答一覧表は「座標」で読む
一覧表を素のテキスト順で読むと ★・CBT・必修/一般/臨床の `○` がどの列のものか判別できない。
`page.get_text('words')` の x 座標で列を切ること（精神科PDFの実測: NO≈54 / 解答≈78 / 国試番号≈109 /
種別★≈154 / CBT≈174 / IRT型≈193 / テーマ≈205 / 疾患名≈361 / 必修≈477 / 一般≈494 / 臨床≈511 / 正答率≈531）。
行のアンカーは NO列（x<62 の数字）に取り、次のアンカーのy手前までを1行とする。

### 何を読むか（正本の順序）
- **巻末の「解答一覧表」が正解・正答率の正本**。NO→解答(a / a,c 等)・国試番号・種別(★)・CBT・必修/一般/臨床・正答率が1表に載る。章の区切り（「2 統合失調症」等）もここで分かる。→ まずこの表を全ページ読んで表化する。
- 各問題ページから**問題文＋選択肢a〜e**を書き起こす（正解/正答率は表から引く）。
- **画像問題**は `page.get_images()` で埋め込みJPEGを抽出し、`{科目}/images/{国試番号}_1.jpeg` として保存。どれがどの設問の図かは画像を目視で確認して割り当てる。
- ⚠️ **`compress_images.py` は「圧縮済みかどうか」を見ずに全画像を再エンコードする**。
  そのまま流すと**既存の2500枚超が2世代目のlossy再圧縮になり、巨大な差分が出る**（実測1800枚前後）。
  さらに知覚ハッシュがわずかに変わるため **`pdf_audit.py` の画像照合が数件余分に落ちる**。
  新科目の画像だけ処理したいときは、実行後に
  `git ls-files -m -z -- '*.jpeg' '*.jpg' '*.png' | xargs -0 -n 200 git checkout --`
  で**追跡済み画像だけ元に戻す**（新規追加ぶんは未追跡なので残る）。その後 `build_image_dims.py` を流し直す。

### ⚠️ 選択肢が表になっている問題 — AI抽出せずユーザーにスクリーンショットを依頼する

**PDFの選択肢が表形式（組合せ問題・行列で選ぶ形式など）の問題は、AIによるテキスト抽出を行わないこと。**
表はテキストとして取り出すと**列の対応がずれ**、a〜eの並びも崩れる。しかも見た目には正しく見えるので、
誤った選択肢がそのままデータに入り、静かに誤採点される（既存データでも「選択肢が表または図」の問題は
この理由で手つかずのまま残してある）。

作業手順:

1. 表形式の選択肢に出くわしたら**その問題で作業を止める**。推測で書き起こさない。
2. **ユーザーに、その問題の選択肢部分のスクリーンショットを撮って送るよう依頼する**
   （どの問題か分かるように国試番号・ページ番号・問題文の冒頭を添えて頼む）。
3. 送られてきた画像を**目視で読んで**選択肢を書き起こす。表のままの方が正確に伝わる場合は
   `<table class="tb">` で組んで `.ch2` は「a　①—②—③」のような組合せラベルにする。
4. 画像として貼る場合は `{科目}/images/` に置き、**📷バッジ(`bi`)と`imgs`を必ず対で**入れる（§4）。
5. どうしてもa〜eの独立した選択肢に落とせない場合は、その問題を飛ばして**ユーザーに報告する**
   （選択肢0個のまま出すと試験モードで解答不能になる）。

他の問題は先に進めてよい。**表の問題だけを保留にし、最後にまとめてスクリーンショットを依頼する**のが効率的。

### 転記はスクラッチに保存しながら
長丁場なので `{SCRATCH}/chNN_transcription.md` に問題文・選択肢・正解・正答率を追記しつつ進める（コンテキスト圧縮対策）。

## 2. 品質基準（産婦人科水準＝これを満たすまで書く）

`questions_{sid}.json` を集計して数値で検証する（下の検証スクリプト参照）。

| 指標 | 目標（obg第1章の実測） | 意味 |
|---|---|---|
| 1問あたり解説ブロック数 | **3.8前後** | ep＋ee＋em＋ept の4枚が基本 |
| 1問あたり解説文字数 | **500字以上** | 病態を機序で書くと届く |
| 1問あたりkw強調数 | **10個以上** | 重要語を色付きで立てる |

### 各問の解説ブロック構成（`.eb` の cls）
1. **`ep` 病態／定義**（青）… 疾患・概念を**機序で段階的に**書く。例「黄体退縮→ホルモン急減→らせん動脈攣縮→虚血壊死→剝脱」。症状学・検査の分類問題でも「その用語の定義＋位置づけ」を1枚書く。
2. **`ee` 選択肢の検討**（緑）… **全選択肢a〜eを1つずつ**「なぜ正解／不正解か」を表で解説。正解肢は `<span class="kw3">◯ …</span>` で強調。**これを全問必須にする**。
3. **`em` 深掘り／覚え方**（紫）… 正解肢の深掘り・ニーモニック・鑑別のコツ・対比。ee表の繰り返しにしない。
4. **`ept` 国試ポイント**（オレンジ枠）… 番号つき複数項目＋**関連疾患・発展知識へ横展開**（例: Asherman症候群, Fitz-Hugh-Curtis症候群）。

### 文章の書き方
- 重要語は `<span class="kw">…</span>`（強調）/ `kw3`（正解・肯定）/ `kw4`（注意・誤り）で色付け。1ブロックに2〜3個。
- 比較・鑑別は `<table class="tb">` で表化すると密度が上がる。
- CSSクラスは study.css が持つ: `.ep .ee .ept .em .ec .ei .kw .kw2 .kw3 .kw4 .tb`。独自クラスを作らない。

## 3. カード/データ構造（HTML→JSON）

章別HTMLは `産婦人科/ch*.html` と同一構造。`build_{sid}_json.py`（obg版のコピー）がHTMLをパースして `questions_{sid}.json` を出す。

カード骨格:
```html
<div class="qc" id="qN">
  <div class="qh">
    <span class="qn">Q.N</span><span class="qe">(国試番号)</span>
    <span class="bg bs">★</span>          <!-- 種別バッジ。bs=★, bc=CBT, bh=必修, bi=📷 画像 -->
    <span class="cr ch">98%</span>          <!-- cr=正答率。ch=緑(≥80) cm=黄(60-79) cl=赤(<60) -->
  </div>
  <div class="qb">
    <div class="qt">症例…<br><strong>問い</strong></div>   <!-- 知識問題は<strong>のみ -->
    <div class="qimg-row"><img src="images/国試番号_1.jpeg" alt=""></div>  <!-- 画像問題のみ -->
    <div class="cs">
      <div class="ch2">ａ　…</div>
      <div class="ch2 ok">ｃ　…</div>       <!-- ok=正解肢。全角字＋全角空白＋本文 -->
    </div>
    <div class="ab"><span class="ai">✅</span><div><div class="ac">正解ラベル</div><div class="as">一言サマリ</div></div></div>
    <div class="eg"><!-- ep→ee→em→ept の順で .eb を並べる --></div>
  </div>
</div>
```

- uid = `{sid}_chNN_qN`（例 `psy_ch01_q1`）。JSONの画像パスは `build`が `images/…`→`{科目}/images/…` に補正する。
- 生成器は**選択肢を `(letter, text, ok, why)` の4つ組**で持ち、`ee`表を自動生成すると肢別解説を書き漏らさない（psy版の`_choice_table`参照）。
- 追加解説（ep/em）は**国試番号キーの`EXTRA`辞書で後付けマージ**すると、選択肢データを壊さず厚みを足せる（psy版参照）。

### ⚠️ 問題番号はPDFの通し番号（NO.）を厳守する

**章ごとにQ.1へ振り直してはいけない。** カードの `id="qN"` と `<span class="qn">Q.N</span>` の N は、
講座PDF巻末の解答一覧表にある **`NO.`（巻を通した連番）そのまま**にする。産婦人科もこの形
（ch01=Q.1〜26／ch02=**Q.27**〜85／ch03=Q.86〜145…）。

- 理由: `jumpToQnum`（study.html）は `.qn` のテキストで問題を探し、「Q番号は科目ごとの連番」
  であることを前提にしている。章ごとに振り直すと**同じ科目内に Q.1 が章の数だけできてジャンプが壊れる**。
  さらに `build_{sid}_json.py` は `id` からuidを作るので、uidも `_q1` だらけになり衝突を起こしかける。
- 実装: 生成器の冒頭に **`Q_START`＝その章の先頭問題のNO.** を置き、
  `render_card(Q_START + idx, q)` とする。セクション見出しの「Q.a〜Q.b」も `Q_START` から計算させ、
  手書きしない（章の問題数が変わるたびにずれるため）。参照実装は `_work/build_psy_ch05.py`。
- 2026-07-28に精神科で実際にこの事故が起きた（ch01〜ch04が全部Q.1始まり）。
  **是正するとuidが変わり、旧uidの学習進捗は引き継がれない**ので、最初から通し番号で作ること。

## 4. 採点・画像の不変条件（壊すと試験モードが無言で誤採点）

- **`ok`が1つも無い問題を作らない**（何を選んでも不正解になる）。
- `ok`の個数＝問題文末尾の「Nつ選べ」と一致（複数正解・採点除外バッジ問題を除く）。
- **📷バッジ(`bi`)と`imgs`の有無を必ず一致**させる。
- 選択肢は `a,b,c…` の順で1つずつ独立要素。結合しない。

### 解答一覧表の「解答＝なし／※採点除外」の問題

国試で採点除外になった問題は解答一覧表の解答欄が `なし`、正答率が `－` になる。この問題だけは
**正解肢0が正しい状態**で、以下3点セットで作る（例: psy ch03 Q.34＝105D-54）:

1. バッジ `('bx','採点除外')`
2. 全選択肢 `ok=False`
3. **正答率スパン `.cr` を出さない**（`rate=None`。`-1` や `0%` を入れない）

`study.html` の `_isScoreExcluded()` はバッジ文字列 `採点除外` か `.as` の本文で判定し、
`_isExamUngraded()` が「採点除外かつ正解肢0」を中立開封（成績に入れない）で通す。
上の検証スクリプトの `sum(ok)>0` は**このバッジを持つ問題だけ例外**にすること。

検証スクリプト（生成後に必ず流す）:
```python
import json,re
d=json.load(open('questions_{sid}.json',encoding='utf-8'))
for ch in d['chapters']:
  for q in ch['qs']:
    assert sum(c['ok'] for c in q['choices'])>0, ('NO OK',q['uid'])
    assert bool(q['imgs'])==any(b['cls']=='bi' for b in q['badges']), ('IMG',q['uid'])
    assert any(e['cls']=='ee' for e in q['eg']), ('NO ee',q['uid'])
```

- 完成の定義＝品質基準(§2)を数値で満たし、不変条件(§4)0件、テスト(§5)全通過、study.htmlで表示・採点できる。

## 7. そのまま使える着手プロンプト（次科目用）

> `MEC問題文pdf/{PDF名}` から新科目 `{sid}`（{科目名}）の章別HTMLを作り、study.htmlへ完全統合する。`_work/新科目HTML生成ガイド.md` の手順・品質基準に従うこと。
> 1. PDFは化けるので fitz でページ画像化して読む。巻末「解答一覧表」を正本に正解・正答率・章区切りを表化。
> 1'. **選択肢が表形式の問題はAI抽出しないで保留にし、まとめてスクリーンショットを依頼すること**（§1）。
> 2. まず第1章だけ、全問を**産婦人科(obg)水準**（1問4ブロック=ep病態＋ee全肢検討表＋em深掘り＋ept国試ポイント、500字/kw10以上）で書く。画像問題は埋め込みJPEGを抽出。
> 3. `_work/build_{sid}_json.py`（obg版コピー）でJSON生成→§4検証→§5統合→テスト。
> 4. 完成したら**ユーザーに第1章をレビュー依頼**（医学的正確性の抜き取り確認を含む）してから次章へ。
