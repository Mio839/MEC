# 消化器（dige）作り直しのループ指示

起動は次の1行だけ（間隔を書かない＝動的モード）:

```
/loop _work/消化器_ループ指示.md を読み、消化器（dige）の作り直しを1イテレーション進める
```

**1イテレーション＝1単位**（①〜④は工程1つ、⑤は6問）。毎回このファイルの「毎回の手順」を頭からやり直すこと。
文脈が圧縮されても進捗を失わないように、正本は会話ではなく `_work/消化器_引き継ぎ.md` に置く。

## 前提（読むもの）

- 工程と不変条件の一般論: CLAUDE.md「既存科目の HTML を作り直すとき」→ `_work/仕様/採点データと科目の作り直し.md`
- 参照実装（5科目すべて①〜⑤を完了）: `_work/内分泌代謝_引き継ぎ.md`（最新・道具の使い方）／`_work/呼吸器_引き継ぎ.md`
- 科目の固有事実と進捗: `_work/消化器_引き継ぎ.md`（初回に作る）

| | |
|---|---|
| prefix / 正本 | `dige` / `questions_dige.json`（全501問） |
| PDF | `MEC問題文pdf/MEC臓器別講座・消化管_問題（表紙2026）.pdf` |
| 画像 | `消化器/images/` |
| 旧章別HTML | `_archive/消化器/`（到達不能・編集対象外） |

## 初回だけ（引き継ぎ.md がまだ無いとき）

1. `_work/消化器_引き継ぎ.md` を内分泌代謝の引き継ぎと同じ形で起こす（表・工程表①〜⑤・道具・固有事実）。
2. `_work/dige_pdf.py` を `endo_pdf.py` のリネームで作り、版面が同じことを確かめる（正規化 diff）。
   違えば固有事実に書く。
3. `python _work/anstable.py dige --dump` で解答一覧表を読み、
   **「一般と臨床が両方 or どちらも無い行: なし」を確認する**（ページ番号バグの検出）。
4. 現状の数字（章構成・問題数・平均字数・画像問の数・`orig_audit.py dige` の初期値）を固有事実に記録する。
5. メモリに `project_dige_rebuild.md` を作り、MEMORY.md の「進行中」に1行足す。

## 毎回の手順

1. `_work/消化器_引き継ぎ.md` の工程表を読み、次の単位を決める。
2. 着手前の3点セット:
   - 引き継ぎ.md の該当章の注意書き
   - 章内の同一テーマの重複（`<strong>` の設問文を difflib で洗う。章をまたぐことにも注意）
   - 対象の問題の PDF 原文と画像（**画像は必ず自分で開いて見る**）
3. 作業する。
   - ① qt の整形 `qt_restyle.py` ／ ② バッジ `badge_sync.py`＋正答率 `rate_sync.py` ／
     ③ 画像の全数検収（`dige_pdf.py images` → ページ描画で人の目で検収） ／ ④ `orig_audit.py dige`
   - ⑤ 6問ずつ。水準と書き方は内分泌代謝の⑤に合わせる（ep/ee/em/ept、cls は共通の命名だけ）。
     **既存の ans_sub は信用しない**：まず設問文と照合 → 次に画像。矛盾があれば PDF を正として直し、
     コミットメッセージと引き継ぎ.md に残す。
4. 検査: `python _work/pdf_audit.py dige` と `node _work/test_subject_totals.js`。
   画像を変えたら `python _work/build_image_dims.py`。
5. `sw.js` の `CACHE` を bump（変更履歴は `_work/sw_changelog.md` の先頭へ）。
6. `git fetch` で ahead/behind を数えてから commit → push（`--amend` 禁止・pre-push の `run_all.js` を通す）。
   メッセージ例: `feat(dige): ⑤ ch03 バッチ12（Q.140〜Q.145 の6問）CACHE v6xx`
7. **次へ進む前に** 引き継ぎ.md の工程表・進捗と、メモリ `project_dige_rebuild.md` を更新する。
8. ScheduleWakeup で次のイテレーションを予約する（delay 60 秒・prompt は上の /loop の1行そのまま）。

## 止まってよいとき（それ以外は止まらず進む）

- 自分の変更でテスト・監査が落ち、直し方が分からない
- PDF と矛盾していて、判断をユーザーに仰ぐ必要がある
- push の衝突など外部要因
- 全501問の⑤が終わった（最後に引き継ぎ.md・メモリ・MEMORY.md を「完了」にして loop を stop）

## 上限やセッションの区切りで止まったとき

- 利用上限で止まると `_work/auto_resume.ps1` がリセット後に `続き` を送る。
  `続き` を受けたら、このファイルの「毎回の手順」から再開し、ScheduleWakeup を張り直すこと。
- 文脈が長くなったら `--autocompact 400000` が同じセッションのまま要約して畳む
  （起動を `claude --autocompact 400000` にしておく）。進捗は引き継ぎ.md にあるので失われない。
