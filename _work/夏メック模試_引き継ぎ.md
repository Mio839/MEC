## 3. 解説HTMLを作るときに要る事実

### 3-1. 1問ぶんの解説の構造（実測の出現数）

```
設問文＋選択肢
出題ポイント          370問（＝全問）
鑑別診断へのプロセス   220問（症例問題だけ）
確 定 診 断           219問
画 像 診 断           103問
英 文 和 訳             5問（英語問題）
選択肢考察            370問（＝全問。○/×/□ ＋ 肢ごとの解説）
正解：ｄ
check point           370問（＝全問。まとまった知識のブロック）
```

⚠️ 「370」は**設問ページの枚数**であって設問数ではない（連問は1ページに複数の設問が載る）。

既存の `questions_*.json` の `eg` 配列へ落とすなら、素直な対応は:

| 解説書 | `cls` |
|---|---|
| 出題ポイント | `ept`（国試ポイント） |
| 鑑別診断へのプロセス／確定診断 | `ee`（鑑別） |
| 画像診断 | `ei`（画像所見） |
| 選択肢考察 | `em`（選択肢別解説） |
| check point | `ep`（病態） |
| 【計算】の式 | `ec`（計算） |

⚠️ **独自クラス名を作らないこと**（`study.css` の6色に意味が焼き込んである）。

### 3-2. 各設問がPDFのどこにあるか

`mock_data/m121s.js` の各問が **`pdf: [開始ページ, 終了ページ]`（1-origin）** を持っている。
解説HTMLを起こすときはここから読めばよく、ページを探し直す必要はない。

```js
window.MecMockData.m121s.questions.find(q => q.uid === 'm121s_A_q27').pdf  // → [57, 58]
```

### 3-3. 画像 —— 解説書PDFに入っている（別冊は要らない）

⚠️⚠️ **「別冊No.○を別に示す」と書かれていても、この解説書PDFでは設問文のすぐ後に
その図が挿入されている。** 本番では別冊に載る図が、解説書では本文に組み込まれている。
**したがって画像は別冊を待たずにこのPDFから抽出できる**（2026-09-08にユーザーが指摘・実測で確認）。

**→ 解説HTMLを作るときは、画像問題の図をPDFから抽出して実装すること。**

| | |
|---|---|
| 図を参照する設問 | **122問**（A32 / B6 / C20 / D35 / E9 / F20）。うち連問が24問 |
| 図の種類 | (ブロック, 別冊No) で **131種**・延べ158参照 |
| データ | `fig: ["13A","13B"]`。⚠️ **別冊No. はブロックごとに1から振り直される**ので、ブロックをまたぐ一意キーは `{ブロック}-{No}` |
| 在りか | **その設問の開始ページ（`pdf[0]`）に埋め込みラスタとして載っている**。連問はグループの先頭ページ（兄弟は同じページ範囲を持つ） |
| 抽出 | `page.get_images()` → `fitz.Pixmap(doc, xref)`。ページ全体では解説書に351枚・230ページぶんある |

⚠️ **4問だけラスタではなくベクター描画**（`B2` ROC曲線 / `C1` 生存数曲線 / `C37` グラフ /
`F33` 聴覚器のシェーマ）。`get_images()` では取れないので、**ページの該当領域を
300dpi で描画して切り出す**こと（`page.get_pixmap(clip=rect)`。他科目で確立している方法と同じ）。

⚠️ **図ラベル（A/B/C）は画像の外に組まれた文字なので、切り出した画像には写らない。**
複数枚の問題は並びが狂っても枚数チェックでは見つからない——循環器の作り直しで
**100問中21問**が狂っていた前科がある。**矩形の直下のラベル文字を拾ってラベル順に並べる**こと
（CLAUDE.md「既存科目のHTMLを作り直すときの不変条件」と同じ手順）。

⚠️ **連問のステムが参照する図は兄弟全員に付ける**（study.html の 2026-09-06 規約）。
`build_mock_m121s.py` はそうしてある。⚠️ その取り落としは静かに起きる——一度、ステムを切る
区切りに半角スペースを許したせいで症例文の書き出し「66 歳の男性。」が設問番号に見え、
**ステムの図を持つ22問ぶんが丸ごと落ちていた**（`fig` が 100問しか無かった）。
`test_mock_score.js` の「別冊の図の索引が壊れていない（122問・131種）」がこれを見張る。

### 3-4. 連問

- **20群**（2連×10群＝B/E、3連×10群＝C/F）。`series: "B41-42"` の形で群を持たせてある。
- 紙面は「次の文を読み、41、42 の問いに答えよ。」＋共通ステム → `41　…` `42　…` の順。
- ⚠️ **共通ステムが参照する図は兄弟全員に付ける**（study.html の 2026-09-06 規約と同じ）。
  `build_mock_m121s.py` はそうしてある。
- ⚠️ 選択肢考察では、サブ設問が**行頭の裸の番号（`41`）**で区切られる。

### 3-5. 計算問題

- 桁入力（マークシートの数字欄）は **3問だけ**: `A74`（3桁・クレアチニンクリアランス）、
  `A75`（3桁・血漿浸透圧）、`D75`（2桁・尿中の1日塩分排泄量）。
- 「※①②③は全て正答で1点」＝**全か無か**。`mock.js` は桁文字列の完全一致で採点する。
- ⚠️ **正解は数値ではなく桁文字列**。先頭ゼロ・末尾ゼロが意味を持つので数値化しないこと
  （`calc_input.js` と同じ約束）。
- 出題テーマに `【計算】` が付く問題は他にもあるが（`B27` 事後確率・`C61` qSOFA など）、
  そちらは**選択式**なので桁入力ではない。

### 3-6. 著作権

⚠️ **問題文・解説の全文をAIへ渡さないこと**（MEC教材の著作物）。
`mock.html` の Markdown 書き出しは、uid・科目・出題テーマ・成績だけを出し、
本文を1文字も含めない（`stats.html` の弱点カルテと同じ方針）。

## 4. 解説の重さをどう受け取るか

解説HTMLは **`MecMock.weights('m121s')` だけを読む**。採点の内部構造には触れない。

```js
{
  "m121s_A_q27": {
    uid, block:'A', no:27,
    weight: 3,              // 0=正解 / 1=誤答 / 2=未解答 / 3=禁忌肢を踏んだ
    state: 'wrong',         // correct | wrong | blank
    picked: 'c', ans: ['e'], taboo: true,
    cat1: '救急・他', cat2: '救急', theme: '電池誤飲への対応',
    pdf: [57, 58]
  }, …
}
```

⚠️ **段の意味を増やすときは `mock.js` の `weights()` と、そこのコメント表の両方を直すこと。**
HTML 側に閾値（`weight >= 2 なら厚く` のような数字）を散らさない——片方だけに新しい段が
入って解釈が食い違う。

⚠️ **`weights()` は「今の周回」の解答から毎回計算される。** 記録として保存されているのは
「何を選んだか」だけで、正誤も得点も保存していない。**解答表を直せば過去の記録も自動で
正しくなる**——これは意図した設計で、正誤を保存する形に戻さないこと。
