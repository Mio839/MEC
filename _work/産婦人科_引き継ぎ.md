### 1問あたりの手順

1. 画像を **全部**開く（`産婦人科/images/*.jpeg`）。細部が要るときは PIL で crop → 4倍拡大。
   PDF の埋め込みは 591×469 程度＝**ファイルが既に原寸**なので、PDFを描き直しても増えない。
2. 📸 ブロック（多くは `eg[0]`）を、**実際に見えているものだけ**で書き直す。
3. ⚠️ **番号（①〜⑤）や記号（A/B）に意味を割り当てている解説は、対応が合っているか必ず確かめる。**
   見ずに書かれた解説は**対応を創作している**（下記の実例）。ずれていたら `em`（選択肢解説）も直す。
4. `ans_sub` が画像と矛盾していないか見る。

### ⚠️ 実際に踏んだ罠

  実物は **②がクスコ式腟鏡**。正解肢 ①の説明そのものが誤りだった。

  **「吸啜刺激」の↓矢印6本と、それに同期した実線Aのスパイク**が描かれている＝これが唯一の決め手。
- **119A-11（腹腔鏡）**：画像に「子宮／左卵管／右卵巣／右卵管」の**標識が焼き込まれている**。

- **110D-50（十二指腸閉鎖）**：`em`（選択肢解説）が**まるごと別の設問の本文**だった
  （「NT肥厚で最も考えられる疾患は」）。見ずに書いた回は**隣の問題の文章を貼り込むことがある**。
- **110F-22（母子健康手帳）**：`ans_sub` が「**推定胎児体重**の推移が下方に偏位」としていたが、

- **115F-46（CTG）**：`em` が「胎児機能不全を示すCTG」としていたが、実物は基線135〜140・

- **117C-55・113C-48（パルトグラム）**：旧解説は「娩出間近」「徐脈など速やかな娩出を要する所見が

  ⚠️ パルトグラムの2つの目盛は**「強くなる向き」が逆**——陣痛周期は上へ行くほど短く、
  陣痛持続時間は下へ行くほど長い。どちらも上が強い、と読むと逆になる。
- **113C-29（母子健康手帳の尿検査欄）**：`−` と `+` の**両方に掛かる横長の楕円は (±)**、

⚠️ **「〜はずである」「〜と考えられ」「〜があれば」は言い訳の変種**。
`obg_img_progress.js` の正規表現は「参照できない」系しか拾わないので、**これらは検出されない**。
点検では文言ではなく**画像と突き合わせて**読むこと。

### ⚠️ 画像ファイルの並び順がずれている（別口の不具合）

複数画像の48問を PDF の版面順と知覚ハッシュで突き合わせたところ、**14問で `_1 _2 _3…` の順が
紙面の①②③…と一致していなかった**（`111H-18_1.jpeg` の中身が③だった等）。
検査と修正は下記。**`--fix` は全部まとめて直してしまうので使わない**——

⚠️ **並べ替えてよいのは「画像内のラベルを自分の目で見た問題だけ」**（CLAUDE.md
「表示側の規約」の *ラベルを拾ってラベル順に並べる*）。版面の位置順がラベル順と一致しない紙面が
実在するため、位置だけで機械的に並べ替えてはいけない。**その問題の画像所見を書くときに
ラベルを見るので、そのついでに直すこと。**

```bash
python _work/verify_obg_img_order.py  # 検査だけ（順序ずれの一覧）
```

⚠️⚠️ **この検査は「OK」を信用してはいけない（偽の OK が出る）。** 版面順を
`(行, 左から)` で並べているので、**2列×3行に組まれた設問では行優先に拾ってしまい、
実際の①②③…（列優先）と食い違ってもずれとして挙がらない**。実例: `115F-30` は
検査が OK と言ったが、実物は `_1=① _2=④ _3=② _4=⑤ _5=③` だった。
**挙がった問題は確かに怪しいが、挙がらなかった問題が正しい保証はない**＝
この一覧は「疑いのリスト」であって合格証ではない。**正本は常にラベルの目視。**

目視確認して直したのは **111H-18 / 114F-33 / 111G-4 / 105E-24 / 115F-30 / 107G-52**
（2026-09-20）と **108I-73 / 106C-9 / 111A-21**（2026-09-21）の **計9問**。⚠️ **115F-30 と 107G-52 は同じずれ方（`①④②⑤③`）だった**——5枚を
2列×3行に組んだ紙面で、ラベルは列優先なのに抽出が行優先になるためで、どちらも検査は「OK」と言った。
**5枚組を見たら順序を疑うこと。**
⚠️ **106C-9 と 111A-21 は検査の一覧に載っていなかった**（106C-9 は丸数字が画像に焼き込まれており
画像そのものが正本、111A-21 は PDF p237 のラベル座標と ncc で確定した）。逆に、検査が挙げていた
`obg_ch06_q264` `obg_ch07_q342` `obg_ch07_q349` `obg_ch10_q526` `obg_ch10_q558` `obg_ch10_q570`
`obg_ch10_q571` `obg_ch10_q578` `obg_ch10_q600` `obg_ch11_q619` と判定不能3問
（`obg_ch05_q197` `obg_ch06_q253` `obg_ch07_q356`）は、**画像所見を書くときにラベルを目視して
「ずれていない」と確認したものが大半**で、残りはラベル自体が画像に無く並び順に意味が無い問題だった。
**検査の一覧は疑いのリストでしかない**という上の注意がそのまま実証された形になっている。

⚠️ 画像の中身を書き換えたら **`python _work/build_image_dims.py`** と
**`sw.js` の `CACHE` bump** を必ず対で行う（ファイル名が変わらないので、bump しないと
全端末が古い画像を掴み続ける）。
