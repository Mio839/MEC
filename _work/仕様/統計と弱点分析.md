## 弱点分析（2026-07-23〜）

「事実の抽出はJS、解釈だけAI」が方針。指標はローカルの決定論コードで計算し、AIには数字の解釈だけ聞く。
AIを呼ばなくても stats.html の弱点カルテとして単体で成立する。

```
attempts.js (mec_attempts_v1)  ← 解答イベントの生ログ（時刻・出題順・所要秒・選んだ肢）
qmeta.json  (build_qmeta.py)   ← 設問形式の自動分類
        ↓
stats.html「🩺 弱点カルテ」     ← 科目×設問形式ヒートマップ／本番正答率帯カーブ
        ↓
「AI相談用にコピー」のMarkdown  ← 集計済みの表だけを渡す（問題文は含めない）
```

- **正誤が記録されるのは試験モード＋SRSのみ**（`_recordMyRate`／`_logAttempt`・study_exam.js）。
  通常モードの「済」はSRSに正解扱いで入るだけで正誤は残らない。分析の母数はこれで確定。
- `questions_*.json` を更新したら `python _work/build_qmeta.py` を流して qmeta.json を作り直す。
- ⚠️⚠️ **カルテの数字は「生の正答率」ではなく「同じ問題の全国正答率との差（pt）」**（2026-09-11〜）。
  「検査」「治療」は全国的にも難しい問題が多いので、生の％で塗ると**問題の難しさを弱点と誤読させる**。
  `buildKarte` は解いた問題ごとに全国正答率を足し込み（`nt`/`nc`/`ne`＝受験回数・正解数・期待正解数）、
  `karteGap` が `自分 − 全国` を返す。**科目単位の平均どうしを引かないこと**（廃止した「📐本番との差」の誤り）。
- 全国正答率は **`RATE`（rate_index.js）を先に引き、無ければ `qmeta.r`** に落とす（`natRateOf`）。
  ⚠️ `rate_index.js` は 2026-07-09 から再生成されておらず、**マイナー講座・公衆衛生の問題を1問も持たない**
  （循環器・呼吸器・肝胆膵の作り直した59問も古い値）。`qmeta.r` は現行の questions_*.json と一致する。
- 上段の **「🚨 優先して潰す弱点」TOP5 は失点（全国並みの期待正解数 − 実際の正解数）の多い順**。
  率だけで並べると「3回中0回」の小さいマスが上に来るため。対象は受験 `KARTE_TOP_MIN_N`(=8) 回以上・
  全国を `KARTE_TOP_GAP`(=5) pt 以上下回るマスだけ。行列の同じマスにも順位の丸印を打つ。
- 配色は **下回り＝暖色4段（`k-d1`〜`k-d4`）／上回り＝青2段（`k-u1`〜`k-u2`）／±5pt 以内＝無彩色**
  （`karteLv`）。赤緑は使わない。全マスに差と自分の％を印字し、タップで読み取り行（`#kReadout`）に全部出す。
- 「全国の正答率帯ごとの自分の正答率」は帯ごとに**全国平均の縦線と、届かなかった幅の斜線**を1本の目盛りに重ねる。
  ⚠️ 旧実装は塗りを `<span>`（インライン）で書いていて `width` が効かず、**4本とも空のバー**だった。
- ⚠️ カルテのマスから study.html へは `?sid=` だけで飛ぶ（マスは「科目×設問形式」なので苦手フィルタとは別の集合）。
- 「🚨苦手問題を解く」・弱点リストの各行は `study.html?state=weak`、「🚩赤旗問題を解く」は `?state=flag`
  （2026-09-27 に直した。それまでは `filter=weak` / `filter=flag` で、study.html が受け付けず「全問」へ落ちていた）。
  study.html の状態フィルタ **🎯苦手（`weak`）** は弱点リストと同じ判定で、**判定式の正本は
  `progress.js` の `MECSync.weakTags(entry, nat)`**（取りこぼし・本番差 `WK_GAP_PT`・反復ミス）。
  ⚠️ 判定を stats.html / study.html に書き直さないこと。サマリーの取りこぼし件数・AI相談の取りこぼし一覧も
  同じ関数を通す（旧実装は `correct/total<0.5` と `round(%)<50` で境目がずれていた）。
  `nat` は整数へ丸めた全国正答率を渡す（study.html はカードの `data-rate` を丸めて渡す）。
- AIへ渡すのは uid・章・形式タグ・成績まで。**問題文・解説の全文は送らない**（MEC教材の著作物）。
  個別に深掘りする場合だけ対象を数問に絞って手で添付する。
- テスト: `node _work/test_attempts.js`（ログ）・`node _work/test_karte.js`（集計）・
  `node _work/test_merge_remote.js`（同期マージ）。いずれも実ソースを読み込むのでロジックの二重管理は無い。

### ⚠️ 📐「本番との差」（科目単位）を作り直さないこと

`renderGap()` は**廃止した**。計算が

```
diff = (自分が試験モードで解いた問題の正答率) − (その科目の全問の本番正答率の平均)
```

で、**引き算の左右で分母が違う**。難問フィルターで解いていればそれだけで差はマイナスへ、
易問ばかりならプラスへ振れる＝数字が何を意味するのか原理的に読めない。

正しい形（**同じ uid どうしの比較**）は弱点リストの **🔻本番差 タグ**と、各行の ▾ を開いた
「本番 N% / 自分 M%」の対比バーとして残してある。`test_stats_sections.js` が
`renderGap` と `gapSec` の復活、および見出しへの「本番との差」の復活を検出する。

### 弱点リスト（統合）

旧・📐本番との差 / 💡取りこぼし問題 / 🎯苦手問題ランキング / 🔍誤答選択肢パターン の4本を
1本に畳んだ。**同じ問題は必ず1行**で、挙がった理由をタグで示す（`weakUnified`）。

| タグ | 条件 |
|---|---|
| 💡取りこぼし | 本番正答率 ≥80% なのに自分は <50% |
| 🔻本番差 | 同じ uid で本番を `WK_GAP_PT`(=40) pt 以上下回る |
| 🔁反復ミス | 試験モードで3回以上受けて <50% |

- 並びは **①タグ数 → ②本番との差 → ③自分の正答率 → ④受験回数**。
  本番正答率が無い問題は差を比べられないので、差を持つ問題の後ろへ回す。
- 上部のチップで理由ごとに絞り込める。**表示は上位 `WK_LIMIT`(=30) 件**で、全件数は下に出す。
- **旧「🔍誤答選択肢パターン」の a〜e 分布は行の ▾（`wkPicks`）へ移した**。
  全体の分布は「どこを直すか」に繋がらないので、セクションではなく末尾の1行に留めてある
  （AI相談Markdownの「誤答選択肢の傾向」は従来どおり出す）。

### 🗺 章別ヒートマップは2段（科目 → 章）

旧実装は **174章を一度に**並べ、どの章なのかは15pxの升目を1つずつタップして
読み取り行（`#hmReadout`）で読むしかなかった。1段目を科目タイルにすると一望する対象が
科目数まで減り、**2段目に章名と正答率をそのまま印字できる**ので読み取り行は廃止した。

- ⚠️ **`hmStat` は章prefixの索引（`_mrByCh` / `_doneByCh`）を引くこと**。章ごとに `myrate`
  を全件走査すると 174章（`chapters_meta.js` の全章）× 全解答の二乗になり、モード切替の
  たびに走る。テストが検査する（2026-08-23 に一度これが落ちて実測 197ms になった）。
- 升目は `.hm-cell` を使い回す＝**ランプの対応表（a1〜a5 / p1〜p5 / n0）を2箇所に持たない**。
- ⚠️ `cleanChTitle` は**「第N章」と「解答解説」で挟んで中身を取る**。講座名は科目名と一致
  しない（内分泌 → 「MEC内分泌代謝」）ので、科目名を頭から削るだけでは「代謝」が残る。
  末尾の「解答解説」は**先に**落とすこと（1つの正規表現に混ぜると、章名の無い title で
  「解答解説」自体が章名として残る）。

### ⚠️ セクションを `display:none` から出入りさせないこと

旧実装は `chartSec` / `gapSec` / `missSec` が**データの有無で**出入りしており、
**日によってページの形が変わって**「あの表はどこだっけ」の原因になっていた。
常設して**中身だけ**を空の状態（`.sec-empty`）に差し替える。

⚠️ **タブ自身の `display:none` はこれに当たらない**（`.tab-pane` は選択で切り替わるだけで、
データの有無では動かない）。禁じているのは「今日はデータが無いから消える」セクション。
畳んだ状態は `.sec.is-collapsed`（`mec_stats_collapse_v1` に `data-sec-id` ごと永続）で、
これも**ユーザーが畳んだときだけ**閉じる。

⚠️ **裏のタブに canvas を置いたら、そのタブを開いたときに描き直すこと。**
`display:none` の中では `offsetWidth` が 0 なので、`renderUnifiedChart()` は
`cv.parentElement.offsetWidth || 300` の**フォールバック 300px で焼き付いてしまう**。
`switchTab('progress')` が再描画を呼ぶのはこのため（消すと推移グラフだけ幅が合わなくなる）。

### 演出（2026-09-11 に「しっかり動かす」で再導入）

`f9c351a`（2026-08-23）で一度ゼロになった演出を、**ユーザーが「しっかり動かす」を選んで**戻した。
過去2回「ページが落ち着かない」で撤去された経緯は伝えたうえでの判断＝**タブを開くたびに入場が走る**

| 仕組み | 実装 |

  インラインで持つので、`transform` のアニメを当てると値が消える（study 側の Phase 7 と同じ罠）。

- ⚠️ 常時動くもの（`infinite`）は **弱点TOPのマスの輪・斜線の流れ・国試リングの光・今日のセル・
  要復習バッジ・主ボタンの光沢・期限切れの棒** に限っている（実測で落ち着いた状態の running が15本）。
  **増やすなら小さい要素だけ**にし、`.qc` のようにたくさん並ぶものへ付けないこと。

  スクリーンショットは DevTools Protocol で撮る（2026-09-11 に踏んだ）。

以下は過去の撤去で得た、**動きを足すときに必ず添える条件**（今も有効）。
- ⚠️ **隠すのは JS が付けたクラスの中でだけ**（旧 `.rv-on .rvs{opacity:0}` の作り）。
  CSS 側だけで `.rvs{opacity:0}` にすると、JS が落ちた日に**ページが丸ごと真っ白**になる。
  `test_stats_sections.js` が「CSS だけで本文を隠していない」を見張っている。
- ⚠️ **隠すのをやめる口は1つに寄せること**。保険で `.in` を付けて回る実装は駄目だった——
  **CSSアニメーションは非表示タブでは進まない**ので `animation-fill-mode:forwards` が適用されず、
  `.in` が付いても `opacity:0` のまま残る（実機で踏んだ。rAF が止まるのと同じ失敗の仕方）。
- ⚠️ **rAF で数字を動かすなら `setTimeout(finish, dur+400)` の落とし所を必ず添える**
  （非表示タブでは rAF が1フレームも来ない）。ハブの `_tweenNum`（index.html）と同じ作り。
  テストは**rAF を使っているのに落とし所が無いときだけ**落ちる。
- ⚠️ **`prefers-reduced-motion` の止めは2重**——`fx-on` を付けない（本体）＋ `@media` で全停止（保険）。
  動きを足すなら**必ず `html.fx-on` の下に**書くこと。
- 「今日」のセルは `.cal-cell.is-today{outline:1.5px solid var(--yl)}` の**静的な印**に加えて、
  2026-09-11 から呼吸（`fxToday`）がある（12週＝84セルの中で今日の位置が毎日ずれるので印は要る）。
  ⚠️ **`outline` は消さないこと**——reduced-motion で動きが止まっても位置が
  わかる二重化で、テストが「outline があること」と「呼吸があるなら reduced-motion で
  止まること」を対で検査する。
