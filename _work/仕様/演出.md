トースト（実績解除・個別ミッション達成）は、**`_annQ` という1本の列に積んで1つずつ再生する**。
テスト: `node _work/test_gamify_ceremony.js`（28件・仮想時計で実ソースを回す）。

⚠️⚠️ **2列（`_cerQ` / `_toastQ`）へ戻さないこと**（2026-08-20に併合した）。旧実装は2本が
**並行に**流れており、そのせいで ① 全画面セレモニーの真上にトーストが重なって両方読めない
② 「あと何件来るか」を数えられない、が同時に起きていた。**位置表示（3 / 4）と授与トレイが
意味を持つ前提条件がこの併合そのもの**なので、見た目や速さのために分けない。

### 授与トレイ ＝ 結果画面の「これから何件来るか」（2026-08-20・Phase 6）

結果画面（`#examOverlay`）の `#gmTrayMount` に **`🎖 今回の獲得 N件` の一覧を先に描く**。
行は未再生＝暗い／再生中＝🔆／済＝✅ で、**残り件数は「まだ暗い行」として常に読める**。
セレモニーはその本編にあたり、隅に `3 / 4` の位置表示を持つ（総数が1件のときは出さない）。

- **飛ばせる**——セレモニー／トーストを**タップすると次へ**、ヘッダの
  **「まとめて受け取る」で残り全部を打ち切る**（`_annSkipAll`）。
  ⚠️ **これを許せるのは「飛ばしても行がトレイに残る＝情報が失われない」から**。
  スキップ時に**音も fx も鳴らさない**（一気に鳴ると事故に聞こえる）。
  ⚠️ タップは**出てから `ANN_TAP_GUARD_MS`(350ms) の間は受け付けない**——入場アニメ中の指は
  結果画面へ向いた指なので、ガードが無いと出た瞬間に消える。
- ⚠️ **総数は `onExamFinish` が返った時点で確定している**（`_bumpMission` も `_afterEvent` も
  同期呼び出し）。だから**あの1行が唯一の描画アンカー**で、あとから行が増えて表がガタつかない。
  獲得0件のセッションだけは `_annPush` が走らず前回の一覧が残るので、同じ場所で `_annDone` を畳む。
- ⚠️ **マウント要素は study.html の結果画面の中にしか置かない**。無いページでは何も描かず
  従来どおり流れる＝**「結果画面だけ」がコード分岐ではなく構造で決まる**。
  他のページへ足すと、そのページでも獲得一覧が出るようになる。
- ⚠️ **位置表示は `.gm-cer` の中ではなく overlay の直下（画面下部）に置く**。中に入れると
  本編の直下＝画面中央付近に来て**トレイの見出しと重なる**（実機で確認して移した）。
  `#gmCerOv` は `inset:0` ではなく **`height:100dvh`** で切る（iOS Safari のツールバーが
  出ていると `inset:0` では下端が画面外へはみ出し、位置表示がツールバーの裏に隠れる）。
- ⚠️ **トーストの `add('show')` には rAF の落とし所を必ず置く**（`setTimeout(...,60)`）。
  非表示タブでは rAF が1フレームも来ないので、保険が無いと**一度も出ないまま寿命だけ尽きる**
  （ハブの `_tweenNum`・統計の `countUp` と同じ穴）。
- **裏タブで全部消化されることはある**（タイマーが間引かれ、戻った瞬間に一気に流れる）。
  これは許容する——**トレイに全件が残るので情報は1つも失われない**。
- reduced-motion では**セレモニーを1件も再生せず、トレイを最初から全点灯**にする。
  ⚠️ ただし**トレイが無い画面では従来どおり再生する**（出さずに捨てると情報が丸ごと失われる）。
- **獲得が多い日の圧縮はしない**（2026-08-20にユーザーが判断）。個別ミッション達成も1件＝1トースト
  なので、調子のいい日は6〜12件・20〜38秒になりうる。件数が見えてスキップできることで受ける設計。

- ⚠️ **`ceremony()` に上書き実装を戻さないこと**。旧実装は overlay の `innerHTML` を
  書き換えるだけでキューが無く、近接して2つ発火すると先の1つが誰にも見られないまま消えた。
  しかもそれが起きる条件が **「40問目の解答」そのもの**で、`onAnswer` の中の
  `_bumpMission → MISSION COMPLETE` の直後、**同じ同期呼び出しの中で**
  `_afterEvent → _checkLevelUp → LEVEL UP` が走り、MISSION COMPLETE は常に消えていた。
- **`opts.fx` / `opts.snd` は積んだ瞬間ではなく、そのセレモニーが実際に出る瞬間に鳴らす**
  （旧実装は積んだ瞬間に鳴っていたので、消えた方の音だけが残っていた）。
- **`toast()` の第4引数 `snd`** も同じ理由で足した。`SND.ach()` / `SND.mission()` を
  `toast()` の外で鳴らすと、保留されたトーストの音だけが試験中に鳴る。
- **`toast()` の第5引数 `label`** はトレイの行に出す文字。`'ミッション達成！'` のような
  汎用タイトルではなく `def.label`（実際に達成したミッション名）を渡す。
  `ceremony()` は `opts.icon` / `opts.label` で同じものを受ける（省略時は `gm-cer-big` から拾う）。

### ACHIEVEMENTS（2件以上の統合セレモニー）はUIテーマ8種ぶんの意匠（2026-09-25〜）

`_playBatchCer`（gamify.js）。カードの骨格は共通（紋章→小見出し→題→罫→件数→番号付きの行）で、

- ⚠️ **UIテーマを増やしたら `ACH_THEME` と CSS の両方に足すこと**（無いテーマは aurora の意匠で出る）。`test_ach_theme.js` が見張る。
- ⚠️ 意匠用の CSS 変数は **`--ach-` 接頭辞必須**（vars.css のトークンを継承で拾う事故の再発防止）。
- ⚠️ 「今回の獲得・達成（N件）」の言葉は残すこと（授与トレイと同じ言葉・`test_gamify_ceremony.js` が見る）。
- 表示時間は 3.2秒＋4行目から1行 0.35秒（上限 5.2秒）。粒子はテーマ色（真鍮は歯車の雨・液体と深海は昇る泡）。

### 試験中は溜めて、結果画面で再生する

`_fxHeld()` が真の間はセレモニーもトーストも**出さずに溜める**。理由は2つ:

1. 全画面セレモニー(2.4秒)は tier 演出の真上に被る。`_microLapFx` / `_lapMilestoneFx` は
   先頭で `examMode` を見て黙るのに、**一番大きいこれだけが素通し**だった。
2. `#gmToast` は `top:14px` 固定＝**iPad では約180pxある試験ヘッダ(`.st-hdr`)の裏**に出る。
   出しても読めないので、出さずに取っておく方が情報が残る。

- ⚠️ **再生の開始は `examMode` 解除の直後ではない**。`showExamSummary` は
  ランクスタンプ(950ms)と祝賀花火(980ms)を自前で走らせるので、そこへ被せると両方読めなくなる。
  **`onExamFinish` が `_quiet(CER_SETTLE_MS=2000)` を置き、その後から再生する**
  （`onExamFinish` は結果画面の末尾で必ず1回呼ばれる＝セッションの終わりを知る唯一の確実な合図。
  この呼び出し自身が生む達成 exam/acc80/perfect も同じ静粛時間に乗る）。
  **この配管のおかげで `study_exam.js` 側の変更はゼロ**。
- ⚠️ **`_afterEvent` に `if (examMode) return;` を足さないこと**。記帳
  （`L.lastLevel` / `L.chDone` / `L.subjDone`）まで止まると
  **試験中に上がったレベルが二度と祝われない**＝取りこぼす。抑止は演出側だけで行う
  （ceremony/toast の保留・`_starGainFx`・章仕切りの光）。
- 保留タイマー `_armHold()` は**溜まっている間だけ1本**張り、解除を検知したら自分で止まる。
- レベルアップが「上がったその場」ではなく結果画面で出るのは**承諾済みの仕様変更**
  （集中を切らないことを優先）。

## 筐体（真鍮固定）と盤面（テーマ可変）の分離（2026-08-19・Phase 4・D1〜D9）

設計の正本は `_work/演出強化_設計.md` §5。**study.css だけで完結する意匠**で、JS を触るのは
稼働灯（D9）の `_updateExamFocus` と cleanup だけ。**`vars.css` / `study.html` / `index.html` には
1行も触れていない**。テスト: `node _work/test_exam_chassis.js`（25件）。

衝突していた前提は2つ——ハブ（index.html）は**真鍮・銅で固定**、試験モードは**演出7テーマで
配色がランダムに変わる**。片方に寄せるともう片方の意味が壊れるので、層を分けた。

| 層 | 色 | 中身 |
|---|---|---|
| **筐体**（シャーシ） | **真鍮固定**。ベース6テーマにも演出7テーマにも振らない | レール（`.st-hdr::before`）・溝（`.exam-prog-track`）・2つのモーダルの額縁と稜線とリベット |
| **盤面**（表示） | 可変。`--or` と意味色 `--yl`/`--gr`/`--rd`/`--blu` | 進捗の塗り・目盛り・難問印・数字・スコアリング・粒子 |

「同じ機械の中にいる」は筐体が、「今どうなっているか」は盤面が担う。**ハブのゲージが既に採っている
分け方**（真鍮の歯車 ⇔ `--or`／`--gr` の弧）と同じなので新しい規約は増えていない。

- ⚠️ **トークン名は「`--exam-` 接頭辞 かつ vars.css に同名が無い」の2条件を必須にすること。**
  `--exam-` は既に共有名前空間で、**vars.css が `--exam-modal-a` / `--exam-modal-b` を持つ**。
  接頭辞を付けただけでは安全ではない（2026-08-14 に `--cb` が vars.css のカード背景色を継承で拾い、
  `animation` ショートハンドが色を duration に食ってプロパティごと `unset` になった事故がある）。
- ⚠️ **`--exam-bevel-lo`（無彩色の暗線）を「見えないから」と省かないこと。** 明線だけだと
  「地が少し明るい帯」に見えるだけで、**明線と暗線の対**になって初めて金属の縁に見える。黒は
  6テーマすべてで中立なので対の片側が常にテーマに依存しない。省くと暖色テーマ（琥珀・薔薇）で
  意匠が消える。実測では**一番弱いのは暖色ではなく既定のインディゴ**（2.09:1・他は2.0〜2.1）で、
  散らばりが 0.19 しかなかったので**テーマ別の作り分けは1つも書いていない**。
- ⚠️ **`.ep-tick` / `.ep-last` を真鍮にしないこと（2026-08-19 に撤回済み）。** 真鍮 `#E0C25E`(L=.5525)
  は `--yl` `#FFB830`(L=.5575) と**輝度がほぼ同一＝1.008:1** で、目盛りは塗りの上にも載るので
  **通過済み区間で完全に消える**。白 .85＋黒縁なら同じ塗りの上で 1.59:1 あり、現に読めている。
  **`.exam-prog` の床（`rgba(0,0,0,.5)`）も黒のまま**——無彩色の方がその上のチャネルとレールが立つ。
- ⚠️ **モーダルの筐体を疑似要素で描かないこと。** `.exam-start-box` と `.exam-modal` は
  どちらも `overflow-y:auto` なので、`position:absolute` の疑似要素は**内容と一緒にスクロールして
  流れる**（章チップを下まで送るとリベットと稜線だけ上へ消える）。`background-image` と
  `box-shadow:inset` はボーダーボックスに固定されるのでこの2つで描く。副産物として**入場アニメも
  不要**（箱ごと `examBoxIn` でスケールインするので筐体も一緒に入る）。
  ⚠️ 2つのモーダルは**必ず1つのルールブロック**（`.exam-start-box,.exam-modal{...}`）で書くこと。
  分けると片方だけ直されて乖離する。面のグラデだけは各自の `--exam-face` に持たせてある。
- ⚠️ **`.qc` には何も足さない。** 層が満杯（`::before`=`exam-scar` / `::after`=UIテーマ全8種の透かしと
  `exam-multi-correct`）で、しかも最大594枚DOMに載る。カードは「問題」であって計器ではない。
- ⚠️ **ヘッダの高さを1pxも増やさないこと。** `_fxBand()` が `.st-hdr` の下端を演出の焦点の基準に
  している。触ってよいのは `background` / `box-shadow` / `border-*color*` の3つだけ。
  ⚠️ **`test_fx_band.js` は `.st-hdr` の高さをスタブしていて CSS を1バイトも読まないのでこの不変
  条件を守らない。** 守るのは `test_exam_chassis.js` の項目3（文字列一致）。
- ⚠️ **`body.exam-effect-*`（演出7テーマ）に筐体の上書きを足さないこと。** 「ネオンのときは筐体も
  光らせたい」は必ず出る発想だが、やると筐体が可変になり Phase 4 の前提そのものが消える。
- ▼で畳んだ状態（`hdr-collapsed`）でも筐体は全部残る。**レールと稼働灯は必ず `.st-hdr` 本体の
  疑似要素に置くこと**（`.st-filter-panel` の中に入れると畳んだ瞬間に消える）。
  ⚠️ **`.st-hdr.hdr-collapsed` のルールは3本のまま**にする（`.exam-prog` を隠すと計器ごと飛ぶ）。

### 動くのは稼働灯（D9）1つだけ

筐体は原則として静止し、自前の `animation` を持つのは **`.st-hdr::after` の稼働灯ただ1つ**。
カードに向かっている間だけレールの上を光が走り、**答えた瞬間に消えて `EXAM_IDLE_BEAT_MS`(1200ms)
の一息を置いてから次のカードで点き直る**。50問セッションでは動く／止まるが50回繰り返され、
**ユーザー自身の解答が刻む拍**になる（Phase 4 で唯一「時間」を持つ演出）。

- **フックは `_updateExamFocus()` の1か所だけ。** ⚠️ `_afterCorrectFx` は**複数選択の経路を
  通らない**し `_tallyQuestion` は3箇所に散る。`_updateExamFocus` は開始・スクロール・解答直後の
  3経路すべてを含む9箇所から呼ばれており、**1関数で全経路を覆えて取りこぼしが構造的に起きない**。
- ⚠️ **タイマー（`_examIdleTimer`）は常に1本。張り直す前に必ず `clearTimeout` する。**
  `_updateExamFocus` はスクロールのたびに走る＝この経路で一番呼ばれる関数なので、
  守らないと確実に多重発火する（`_armHold`・`_startGaugeAmbient` で同じ型の前科が2件ある）。
- ⚠️ **消灯は `opacity` だけで受ける。** クラスで `animation` ごと外すと `transform` が基準値へ
  戻って光が始点へ飛び、`animation-play-state:paused` だと途中で凍って「固まった」に見える。
  `animation` は掛けっぱなしにする。
- ⚠️ **レールは `::before`・稼働灯は `::after`。** 逆にすると後から描かれる光がレールの下に隠れる。
- ⚠️⚠️ **光は「箱の外へ出る要素」ではなく「箱いっぱいの要素の中を動く `background`」で作ること。**
  初版は `width:26%` の疑似要素を `translateX(-110%→395%)` で走らせており、**右端が包含ブロックの
  128%（1905px 幅で右へ約547px）まではみ出していた**。デスクトップ Chrome は文書のスクロール領域を
  広げないので気づけないが、**iOS Safari は右へあふれた内容に合わせてレイアウトビューポートを広げる**
  ため、`width=device-width` の下で**ページの縮尺が1.4秒周期で勝手に伸び縮みし続けた**
  （「試験中に勝手にピンチアウトして元に戻るのが終わらない」＝2026-08-19 に実機で発生）。
  `left:0;right:0` で箱に固定し `background-position` を動かせば geometry は1pxも動かない。
  `position:sticky` の疑似要素に無限の `transform` を掛けない、という意味でも安全になる。
  `test_exam_chassis.js` の項目15b が「`width` を持たない・`transform` を使わない・端で光が
  見切れない振り幅がある」を検査する。
- ⚠️ **cleanup（`exitExam`）で点灯クラスとタイマーの両方を落とすこと。** 残ると通常閲覧のヘッダで
  光が走り続ける。
- **周期 `--exam-idle-cycle` は 1.4s。長くしないこと**——問題文を読んでいる空白は8〜15秒しか
  ないので、4〜6秒の「呼吸」だと1周も回りきらずに毎回途中で止まる＝ちらつきに見える。
- `EXAM_IDLE_DELAY_MS`（点灯までの遅延）の**既定は 0**。倒す先の候補は `FAST_TIER_MS[2]`（2026-08-25に 7000→12000）
  （速答3段の「速答ではない」の境目）で、そうすると**褒める区間は静かで褒めない区間だけ機械が
  回る**という筋が通り新しい定数も要らない。⚠️ 値は推測せず `mec_attempts_v1` の所要秒から決める。
- reduced-motion では `_fxOff()` が点灯クラスを一度も付けない（vars.css の `@media` でも二重に
  止まる）。**光が消えてもレール・稜線・リベット・チャネルは残る**ので「消えるだけ」にはならない。
- 逃げ道: ラストスパートと重なって「うるさい」場合は
  `body.exam-mode.exam-sprint .st-hdr::after{opacity:0;}` の1行で消せる。

### ⚠️ 試験開始の直後だけ `.exam-key-focus` が付かない（Phase 4 以前からの既存の穴）

`startExam` の `requestAnimationFrame(_updateExamFocus)` は**カードが出そろう前に1度走るだけ**で、
そのあと再実行の機会が無い（次に走るのは最初のスクロールか解答）。そのため試験を開始した直後は
`.exam-key-focus` が誰にも付いておらず、`_markCardSeen` も呼ばれない。

- **Phase 4 が作った不具合ではない**（`_getExamTargetCard` と焦点クラスを立てる3行は HEAD と
  バイト単位で同一。2026-08-19 に確認済み）。ただし**稼働灯がこの状態にぶら下がっているので、
  1問目をスクロールせずに解くと稼働灯が一度も点かない**という形で初めて表面化した。
- **2026-08-19 にユーザーが「許容できる」と判断した＝直さない。** 稼働灯は情報を持たない付加物で、
  これが点かなくても読めなくなる情報は1つも無い（レール・稜線・リベット・チャネルは静的に残る）。
  気が変わったときのために書いておくと、直すなら `startExam` の rAF を「カウントダウンが明けた
  後にもう一度」呼ぶ形が素直。**手を出すのはそのときだけにすること**——見かけの穴に見えるので

## 演出の予算・reduced-motion・後始末（2026-08-31・レビュー対応）

演出コードのレビューで見つかった構造的な問題への対処。テスト: 既存37本に加えて
`node _work/test_dynamic_fx.js` を**文字列検索から到達可能性の検査へ**書き換えてある。

### ⚠️ 全画面レイヤーは1解答につき1枚（`FULLSCREEN_BUDGET`）

⚠️ **2026-09-28 に study 側は暗転そのものを外したので、`FULLSCREEN_BUDGET` / `_fsTake` も消えた**（下は経緯。全画面を覆う層を足さないこと）。

旧実装は上限が無く、tier4 の1解答で **暗転(backdrop-filter) / フラッシュ / 特大×n /
外周ボーダー / 背景ブレスの5枚**が同時に重なり、読ませたい演出（A4 リボン・A5 沈み込み）が
埋もれていた。`_showStreakEffect` が `_fsBudgetReset()` してから `_fsTake()` で取り合う。

- **消費するのは面を覆うものだけ**＝`_triggerTimeStop` / `_triggerFullscreenCombo` /
  `_spawnCRTOverlay`。優先順は暗転 ＞ 特大×n ＞ CRT。
- **予算の外**: `_triggerBorderGlow`（縁だけ）・`_triggerBgBreath`（alpha .12 の環境光）・
  粒子・トースト・コンボメーター・カード上の演出。
- ⚠️⚠️ **上限を上げて派手さを出そうとしないこと。** 段が上がったときに増やすのは
  「枚数」ではなく「1枚の強さ」（色・持続・スケール）。
- ⚠️ **特大×n は tier6（14連続）以上へ格下げした**（§情報設計）。あれが伝えるのは連続数だけで、
  同じ数字をトーストとコンボメーターが既に持っている＝画面全体を使う価値がいちばん低い。
  代わりに `.exam-mark-pop`（難問突破・リベンジ・初見突破）を 12.5px → 15px にした。
- **派手さの置き場は結果画面**（`showExamSummary`）。読むべき本文がもう無く、セッションの
  終わりという滅多に来ない瞬間なので制約が掛からない。PERFECT のみ花火16発＋紙吹雪240片。

### ⚠️ reduced-motion は「DOM演出」と「粒子」の両方を止める

- `_showStreakEffect` の先頭に `_fxOff()` ガードがある。**外さないこと。**
  以前は無く、MecFX（粒子）だけ止まって **全画面フラッシュ・特大×n・暗転・シェイク・
  外周ボーダー・背景ブレス・浮遊コンボは素通り**していた＝「動きを減らす」を選んだ人に
  いちばん強い層だけが残るという逆転。⚠️ コンボメーターだけは情報なので残す。
- 粒子側は **`MecFX.setEnabled(bool)`**（fx_engine.js の `addP` / `attractor` で弾く）。
  ⚠️⚠️ **旧方式（`MecFX[k] = function(){}` で全メソッドを潰す）へ戻さないこと。**
  ① 判定が `load` 時の1回きりで OS 設定の変更に追随しない
  ② 潰したメソッドは戻せない＝ONで起動して途中でOFFにすると粒子が二度と出ない。
  study.html と chapter_exam.js の両方が `matchMedia('...').addEventListener('change')` を
  購読して同期する。
- `ui_theme.css` に**全停止ブロック**がある（`animation-duration:1ms` へ潰す形）。
  ⚠️ `animation: none` にしないこと。8テーマ全部が `.qc` に `{id}CardEnter … both`
  （`from{opacity:0}`）を掛けているので、fill-mode ごと消すと**カードが白紙になる**。

### ⚠️ 全画面フラッシュの明滅は 2.8Hz 以下（`FLASH_CYCLE_MS = 360`）

`#examStreakFlash` は `inset:0` の全画面。旧実装は 85ms 刻みで 0.95↔0.06 を往復＝
**1周期170ms＝5.9Hz** で、WCAG 2.3.1 の「1秒に3回まで」を超えていた（ecg の tier5 は
`rgba(255,23,68,.65)` ＝飽和した赤で、赤色フラッシュはさらに厳しい基準の対象）。
いまは1周期360ms・暗側も 0.42 で輝度の振れ幅を半分以下にしてある。
⚠️ **段の派手さを明滅の速さで出さないこと。**

### ⚠️ 演出の遅延は `_fxTimeout()` を通す（§cleanup）

study_exam.js の setTimeout 64本のうち `clearTimeout` されていたのは10本だけで、
残りは試験を抜けても走り続けていた（正解直後に「終了」を押すと、**通常閲覧の画面に
演出DOMが生えてから消える**／`MecFX.clear()` の後から粒子が撒き直される）。

- `_fxTimeout(fn, ms)` が登録簿 `_fxTimers` に積み、`exitExam` の**先頭**で `_fxClearTimers()`。
  ⚠️ 掃除より先に止めること。後にすると掃除の直後に遅延ぶんが新しい演出を生やす。
- ⚠️ **「試験を抜けた後も動いてよいもの」は素の setTimeout のまま**にすること
  （`_stampRank` / `showExamSummary` の祝賀は exitExam の後に動くのが正しい）。

### ⚠️ 可視帯 `_fxBand()` は 16ms キャッシュ

`.st-hdr` の `getBoundingClientRect()` を同期で読む関数が40箇所から呼ばれ、
`_examClampFxXY` が内部でもう一度呼ぶので **1解答あたり15〜20回**のレイアウト読みになり、
その合間に style を書くので read→write→read の Layout Thrashing が起きていた。

- `FX_BAND_TTL_MS = 16`（60fps の1コマ）。⚠️ **伸ばさないこと**（スクロール中に古い帯へ出る）。
- 無効化は `_fxBandInvalidate()`＝window の resize と **visualViewport の resize/scroll**。
  ⚠️ 口を減らさないこと（iOS のツールバー出入り・分割表示・ピンチ・ソフトキーボード）。
- ⚠️ **rAF でキャッシュを無効化しないこと**——非表示タブでは rAF が1コマも来ないので、
  裏に回した瞬間の帯が永久に固まる。

### ⚠️ `.qc` を全走査しない／`.qc` の疑似要素に `infinite` を置かない

- `card-heat-*` の消灯は `_heatedCard` の参照1つで行う。旧実装は

## 省電力＝iPad・スマホだけ常時アニメを減らす（2026-09-25〜）

`html.mec-lite` を **study.html 冒頭のスクリプト**が付ける（`ios-no-cv` と同じ判定＋`(hover:none) and (pointer:coarse)`＋Android/Mobi）。

### 見た目を変えずに描画を軽くする（全端末・2026-09-25〜）

- **GPUだけで動く脈動**（study.css「GPUだけで動く脈動」）: `box-shadow` / `border-color` / `background-position` を
  動かすアニメは毎フレーム描き直しになるので、一度だけ描いた層の `opacity` / `translate` を動かす形へ置き換えた。

    `!important` はアニメより強い（headless Chrome で実測・値が動かない）。計算だけ毎フレーム走っていた。

  - Abyss の泡（`body::after`）: `background-position` → `translate`（`abyssBubbleDriftGpu`）。

    Abyss の `.qc` 模様、liquid の正解肢の `border-radius` は出る場面が限られるので据え置き。

  ⚠️ 間引いたコマでも rAF は必ず張り直すこと（張らないとループが止まる）。
