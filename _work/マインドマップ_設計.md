### 1-2. 既存9マップの章リンクは全部死んでいる

各マップは `link:'ch01_blood_basics.html'` の形で章別解答解説HTMLを指しているが、
**章別HTMLは2026-07-07に `_archive/{科目}/` へ移動済み**（CLAUDE.md に記載のとおり）。

- **9科目87本のリンクすべてが404**（循環器だけは章HTMLがフォルダに残っているので現状は生きている）
- **画像も21枚が404**（神経7・消化器13・血液1）。`imgs:['images/107A-61_1.jpeg']` が存在しない

つまり現状のマップは「疾患名と要点は読めるが、そこから先へ進めない」。
役割が「俯瞰・想起」であっても、**押して404が返るのは想起の流れを切る**ので修復対象。

### 1-3. 21科目は現レイアウトに幾何学的に載らない

統合マップは1周360°を科目数で割る設計（9科目＝40°間隔・`fanDeg = min(30, 8+6*疾患数)`）。

- 21科目 → **17.1°間隔**。fan は14°までしか取れない
- R2=710 で14°の弧＝**173px**。直径54px（`NR=27`）の疾患ノードは**3個で埋まる**

**データを足すだけでは必ず衝突する**＝レイアウトアルゴリズムの作り直しが前提条件。

同じ破綻が科目マップ側にもある。`_work/mindmap_generation_prompt.md` の角度配分表は**11章まで**しか
持っていないが、**感染症は22章**ある。

### 1-4. 「重い」の主因はノード数ではない

72ノード・約800要素はSVGとしては軽量な部類。実際の支配項は描画方式だった。

| 原因 | 何が起きているか |
|---|---|
| **2000×2000のSVGをCSS `transform:scale` で拡縮** | ドラッグ/ピンチ中は `will-change:transform` でレイヤー昇格する。scale=3 のとき **6000×6000×4B ≒ 144MB のテクスチャ**。iPadが最初に音を上げるのはここ |
| `feGaussianBlur stdDeviation:55` の星雲ブラー×10 ＋ `glow`/`glow2` | 拡縮のたびに巨大領域を再ブラー |
| `flow` / `travelDot` / `orbitSpin` / `twinkle` / `pulse` が **infinite** | 何もしていない間もCPUを食い続ける。`travelDot` は `filter:url(#glow2)` 付き＝毎フレーム再ブラー |
| 折りたたんだ科目のノードが `opacity:0` でDOMに残る | `disCreated[si]` で作り直しを止めているため、開閉を繰り返すとDOMが単調増加 |
| `touchmove` ごとに `clampAndApply()` | 上記が直れば消えるはずだが、rAFスロットルへ寄せる |

`isMobile`（`navigator.maxTouchPoints>0`）でフィルタと星の一部は既に落ちているので、
**iPadは既に「軽い方の経路」にいてなお重い**。残る犯人は巨大レイヤーと常時アニメ。

→ **ノードを減らす方向の対策は的外れ**。viewBox駆動へ変えてフィルタと常時アニメを落とすのが本筋で、
これは小さい改修で効く。

### 1-5. エンジンが9本に分裂している

9マップはそれぞれ自前のエンジンを内蔵し、既に書き方が乖離している（`isMobile` ガードは統合マップにしか無い）。
**このまま21本へ増やすと、CLAUDE.md が繰り返し警告している study_exam.js ⇔ chapter_exam.js の
ミラー乖離を21方向で踏む**（あちらは `check_effect_themes_sync.js` という専用の見張りを立ててやっと
釣り合っている）。

### 1-6. `sw.js` がマインドマップを1バイトもキャッシュしていない

`SHELL` / `CARDS` のどちらにも `mindmap` の文字が無い＝**オフラインで開けない**。

## 2. 役割から導かれる設計原則

役割が **「直前期の俯瞰・想起」** に決まったことで、何を優先し何を捨てるかが決まる。

1. **主役は「疾患ノードの配置」と「国試ポイント4行」**。ここの質がこの機能の価値のほぼ全部。
2. **リンクは補助。ただし404は許されない**。押して何も起きないより、押さない方がまだいい。
   行き先は `study.html?sid={prefix}` の1本で十分（study.html が受け取るパラメータは
   `sid` / `filter` / `mode` の3つだけで、章・問題番号ジャンプは存在しない）。
3. **進捗オーバーレイ（済み率・正答率でノードを塗る）は入れない**。
   系統色（病態グループ）という意味の色が既に載っているところへ別軸の色を重ねると、両方読めなくなる。
   ⚠️ これは Phase 4 の「筐体は真鍮固定／盤面は意味色」と同じ論理で、**1つの面に2つの意味を持たせない**。
   弱点の可視化は stats.html の弱点カルテ・弱点リストが既に担当している。
4. **検索窓は入れる**。想起の起点は「あの疾患どこだっけ」なので、科目マップ内で疾患名を絞れると効く。
   ヒットしたノードへ `panTo` する。ハブ側では科目名の絞り込みに留める。
5. **動くものを置かない**。試験モードの演出（Phase 4/5）は「読んでいる8〜15秒を埋める」ためのもので
   目的が違う。こちらは**眺めて思い出す道具**なので、動くものがあると視線が持っていかれる。

## 5. レイアウト

### 5-1. ハブ（統合マップ・21科目）

- 中心 `MEC` → **21科目ノードを1周に配置**（17.1°間隔）。**科目ノードだけは常時表示**。
- **疾患ノードは展開中の科目にだけ描く**。
- 展開時、その科目は**両隣が閉じていれば隣の角度を借りる**（実効fan 17°→最大51°）。
  借りられる角度は「隣が閉じているか」で毎回計算し直す。
- **同時展開は3科目まで**（4つ目を開いたら最も古いものを閉じる）。
- **「全科目展開」ボタンは廃止**。21科目×平均9疾患＝約190ノードを同時に置くと、
  どの科目も隣の角度を借りられず**必ず衝突する**（廃止は幾何の要請であって好みではない）。
  代わりに **「コア12を展開」「マイナー9を展開」**……も同じ理由で置けない。
  ボタンは **「すべて閉じる」1つだけ**にする。
- 科目間 CROSS リンクは**両端の科目が両方展開中のときだけ**表示（現行仕様を踏襲）。

⚠️ ハブの疾患ノードは**各科目の代表疾患のみ**（chapters を横断して上位8〜10）。
全疾患を出すのは科目マップの仕事で、ハブでやると角度を借りても足りない。
代表疾患の選定は `mindmap_data/index.js` に**科目ごとの疾患IDリスト**として持つ
（データを二重に持たず、科目データのIDを参照するだけ）。

### 5-2. 科目マップ（章数から角度を自動計算）

```
angle_i  = -90 + 360 * i / N          // N = 章数
spacing  = 360 / N
fan_i    = min(spacing - MARGIN_DEG, 8 + 6 * 疾患数_i)
```

- `MARGIN_DEG` は隣章との最小余白。現行の 8章/40°間隔/fan36° は余白4°で組まれているので、
  同等の見え方になる値を定数で置く。
- ~~章数 > 12 の科目は2重リング（内輪＝前半・外輪＝後半）へ落とす~~
  → **実装時に不要になった（下記 §11-2）**。扇の中で子を多重リングに積む方式に一本化したので、
  章ノードは常に1周のまま、章数22でも科目数21でも同じアルゴリズムで載る。

⚠️ `_work/mindmap_generation_prompt.md` の「fanDeg は36°上限」「8章なら -90,-45,0,…」という
**手計算の角度表はこの自動計算に置き換えて廃止する**。あの表があるかぎり、
表に載っていない章数の科目が来たときに人間が勘で埋めることになる。

### 5-3. 衝突をテストで守る

`_work/test_mindmap_layout.js` を新設し、**21科目ぶんのレイアウトを実データで計算して、
ノード同士の最小中心間距離が `nodeR*2 + 4` を下回らないこと**を検査する。
実ソース（mindmap.js）を読み込む形にして、ロジックの二重管理をしない（既存テスト群と同じ流儀）。
CLAUDE.md の「テスト一覧」へ追加する。

## 6. 描画方式（「重い」の根治）

| 現状 | 対策 |
|---|---|
| 2000×2000 SVG を CSS `transform` で拡縮 | **viewBox 駆動**へ。svg は `#wrap` に 100%/100% で貼り、pan/zoom は `viewBox="x y w h"` の書き換えで行う。テクスチャは常にビューポート大に収まる（144MB → 数MB） |
| SVGフィルタ（星雲ブラー・glow・glow2） | **全廃**。glow は半透明の同心円2枚を重ねて焼く。星雲は `<radialGradient>` の塗りで出す（ブラー不要） |
| `flow`/`travelDot`/`orbitSpin`/`twinkle`/`pulse` が infinite | **常時アニメを全廃**。動くのは「タップした瞬間の0.6秒」だけ（shockwave と drawOn は一度きりなので残す） |
| 折りたたんだノードが `opacity:0` でDOMに残る | 折りたたみで `remove()` する。`disCreated` フラグを捨て毎回作り直す（80ノードの生成は1ms未満） |
| `touchmove` ごとに transform 更新 | rAF スロットル（1フレーム1回）へ |

### ⚠️ 不変条件（後から「かっこいいから」で戻したくなるもの）

1. **マインドマップに `infinite` アニメーションを1つも置かない。**
   試験モードの Phase 4/5 は「読んでいる8〜15秒を埋める」ためのもので目的が違う。
   ここは眺めて思い出す道具であり、動くものは視線を奪って想起を妨げる。
2. **SVGフィルタ（`filter:url(#…)`）を使わない。** glow が欲しくなったら同心円で焼く。
3. **巨大SVGをCSS `transform:scale` で拡縮しない。** 拡縮は viewBox で行う。
   これを破ると iPad で 100MB級のテクスチャが再発する。
4. reduced-motion では shockwave と panTo のイージングも切る。

### 期待値

ノード数が72→約200になっても、**フィルタと常時アニメが消えれば今より軽くなる**。
描画コストの支配項がノード数ではないため。
Canvas への作り直しは**不要**（`fx_engine.js` の資産はあるが、200ノードでSVGが苦しむことはない）。
将来500ノードを超えたら再考する、という条件付きで見送る。

## 7. 移行の手順（既存9科目）

1. **`_work/extract_mindmap_data.js` を作る**（Python の正規表現ではなく **Node の `vm` でHTML内の

4. **9科目ぶんの表示確認**。⚠️ **`file://` では動かない**（`fetch`／モジュール読み込みが全滅）。
   `127.0.0.1` の `python -m http.server` で開く
5. 旧 `{科目}/mindmap.html` をリダイレクトstubへ置換
6. `index.html` の `MINDMAP_TOOL.maps` を `mindmap.html?sid=` 形式へ書き換え

### 8-2. マイナー8科目は CLAUDE.md が下書きになっている

ent / uro / ortho / anes / rad / tox については、CLAUDE.md に
**「本章の軸は…」「章を貫く筋は4本」「最難は NO.X（正答率Y%）＝…」** がびっしり書かれている。
これは**疾患ノードの keys そのもの**であり、しかも一度PDF原文と突き合わせて検証済みの記述。
ここから起こすのが最も速く、精度も高い。

例（uro ch06）：「熱があるかで下部（粘膜）と上部・実質を割る」「腎盂腎炎の診察はCVA叩打痛ただ1つ」
「抗菌薬で治らない尿路感染は閉塞・膿瘍の問題」「尿道炎は淋菌かクラミジアかの二択」
→ そのまま4つの疾患ノードの key になる。

### 8-3. 1科目ぶんの手順（1セッション1〜2科目）

1. `questions_{sid}.json` の章構成を読む
2. CLAUDE.md の該当科目の「軸」「最難問題」記述を読む
3. 章ごとに疾患5〜8個を選び、`keys` 4行を書く
4. `relations` を国試で問われる鑑別・合併に限って5〜12本
5. **ユーザーが医学的に検査 → 修正 → commit**

### 8-4. keys の品質基準

⚠️ **書いてよいのは、数値・略語・鑑別の分岐を含む具体的な記述だけ。**
「重要」「頻出」「注意が必要」のような形容は1行使って何も伝えないので禁止。

| やらない | 理由 |
|---|---|

## 11. 段Aの実装で設計から変えたこと（2026-08-21）

実装しながら前提が崩れた点。**なぜ変えたか**を残す（元の案に戻したくなったときの材料）。

### 11-1. `group`（系統色）は取り下げ、データから色を消した

設計は「章の `color` を `group`（系統名）に置き換え、エンジンの `GROUPS` 表が色を引く」としていた。
これは `_work/mindmap_generation_prompt.md` の「各章を病態系統でグループ化し、系統ごとに色を統一する」を
前提にしていたが、**実データを調べたらその規約は一度も守られていなかった**。

```
内分泌 ch01 内分泌の基本  #D97706（橙＝「代謝・内分泌」系のはず）
内分泌 ch09 脂質代謝      #DC2626（赤＝「炎症・感染」系のはず）
内分泌 ch04 甲状腺        #047857（緑＝「自己免疫」系のはず）
```

9科目78章すべてがこの調子で、**色は「隣の章と見分けるための回転パレット」**として使われていた。
`group` を被せても意味を持たない名前が増えるだけなので、**データから色を消し、
エンジンが `MM_PALETTE[章index % 11]` を引く**形にした。

- 隣接章が必ず違う色になることが**構造的に保証**される（作者の記憶に依存しない）
- 新科目のデータに色の判断が1つも要らなくなる
- 系統で塗り分けたくなったら、**意味のある軸を別に設計してから**入れること。
  色コードを各データファイルへ散らすのは、その時でも解にならない。

### 11-2. 2重リングは要らなくなった（扇の中で積む）

「章数>12 の科目は章ノードを2重リングにする」としていたが、**扇の中で子を多重リングに積む**
方式にしたら不要になった。

```
各親の扇 = min(子が1リングに収まる幅, 隣に迷惑をかけない上限)
扇に入りきらない子は R2 + k*RING_STEP の外側リングへ積む
```

これで**章22（感染症）も科目21（ハブ）も同じ1つの関数**で載る。章ノードは常に1周のまま。
`_work/test_mindmap_layout.js` が 22章×6疾患と21科目×8疾患の両方を実際に計算して衝突を検査する。

⚠️ **扇の幅に `min(必要なぶん, 上限)` の `min` を必ず残すこと。** これを外すと、余裕のある
科目マップでも扇が開閉のたびに伸び縮みして**ノードの位置が動く**＝「どこにあったか」の記憶が壊れる。
テスト §5 が「1章を閉じても他章の疾患が1pxも動かない」を見張る。

### 11-3. ハブは科目マップの射影ではなかった

設計は「代表疾患の選定は index.js に科目データのIDリストとして持つ（データを二重に持たない）」
としていた。実データを突き合わせたところ、**ハブの72疾患のうち科目マップに対応するラベルは55件しかなく**、
`keys` の粒度も違った（ハブは科目全体を俯瞰する高さで書かれている）。

→ ハブは**独立にキュレーションされた見取り図**として `mindmap_data/_hub.js` にそのまま引き継いだ。
段Cで新科目を足すときは、科目データとハブの代表疾患8つを別々に書く。
これは重複ではなく、**「その科目を定義する8つ」を選ぶ作業**として意味がある。

### 11-4. 科目メタの正本は `gamify.js` の SUBJECTS

科目の name / icon / color が**3系統に割れていた**（gamify.js／chapters_meta.js 由来の
index.html MINDMAP_TOOL／旧統合マップの独自パレット）。全21科目を持っていて、レベル・実績・
科目制覇が既に見ている `gamify.js` の `SUBJECTS` を正本にし、`mindmap_data/index.js` を
そこから機械生成する（`node _work/build_mindmap_index.js`）。
`index.html` の `MINDMAP_TOOL.maps` は**ゲッターに変えてレジストリから導出**する＝一覧を二重に持たない。

### 11-5. 実装中に踏んだ落とし穴

| 症状 | 原因 | 対策 |
|---|---|---|
| 地図が画面中央で豆粒になる（ハブ・全部閉じた状態） | `fit()` が背景の目盛り円まで測っていた。目盛り円は疾患リングの大きさで描かれるので、中身が中心の10ノードだけでも外形は疾患リングぶんになる | 背景（`lBg`）と演出（`lFx`）を**測定から外す**。`unionBBox()` が内容レイヤーだけの外形を返す |
| 縦に27%の余白が出る | レイアウトの計算値（`extent`）から見積もっていた。ラベルの張り出しを当て推量で足していた | **`getBBox()` の実測**で合わせる |
| 科目を連続でタップするとレンダラが応答しなくなる（スクリーンショットが30秒タイムアウト） | `panTo` が呼ばれるたびに新しい rAF ループが立ち、複数のループが同じ `view` を奪い合っていた | **走るアニメーションは常に1本**（`animToken` で世代を持ち、古いループは自分で降りる） |
| 展開しても「何も増えていない」ように見える | 親ノードの座標へ `panTo` していたが、子は外側のリングに出るので画面に親しか写らない | `focusParent()` が**親＋その子＋中心**が収まるところまで寄る |
| 検索で「梗塞」の1位が『神経画像・検査』 | `keys` の本文にも当たるため | **疾患名の一致を先に出す**（前方一致 → 部分一致 → keys 一致） |
| テストの「`filter:url(` を使っていない」が誤検出で落ちる | **禁止した語を「なぜ禁止か」の注意書きにわざと書いている** | 検査の前に**コメントを落とす**（`stripComments`） |
